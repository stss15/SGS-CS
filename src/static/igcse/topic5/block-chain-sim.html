🏛️ Centralised vs Decentralised Systems

Understanding why blockchain was invented

Before we build a block, we need to understand the problem blockchain solves. Today, when you send money online, a central authority (like a bank) verifies and records the transaction. But what if that bank makes an error, gets hacked, or censors your transaction?

🌐 The Peer-to-Peer Network

Every node holds an identical copy of the blockchain

A blockchain network is made up of nodes — computers run by volunteers, companies, or miners around the world. Each node independently stores, validates, and relays data. There is no master server. When one node receives new information, it shares it with its neighbours, who share it with theirs, until the entire network is updated.
Click "Broadcast a Transaction" to see how data spreads
How does data spread? This is called gossip protocol. When Alice sends a transaction, her node tells its connected peers, those peers tell their peers, and within seconds the entire network knows about it. Each node independently verifies that the transaction is valid before passing it on.
What happens if a node lies? Every other node checks the data against the protocol rules. If a node sends invalid data, the other nodes simply reject it and ignore that node. The honest majority always wins — this is the foundation of blockchain security.

💸 Transactions & The Mempool

Where transactions wait before being included in a block

When you send cryptocurrency, your transaction doesn't go into a block immediately. It first enters a waiting area called the mempool (memory pool). Think of it as a queue. Miners select transactions from the mempool to include in the next block they're trying to mine.
Digital signatures: Every transaction is digitally signed using the sender's private key. Nodes verify it using the sender's public key. This proves the sender authorised the transaction without revealing their private key — the same public-key cryptography you study in IGCSE.

Why do miners choose which transactions to include? In real blockchains, each transaction includes a small fee. Miners prioritise transactions with higher fees because they get to keep those fees as a reward. This is why transactions can be slow when the network is busy — your low-fee transaction stays in the mempool longer.

🧱 Block Structure

What's actually inside a block?

A miner takes transactions from the mempool and packages them into a candidate block. Before it can be added to the chain, the miner must fill in all the required fields. Here's what a block contains:
#

Block Index

The block's position in the chain (0 = genesis block)

🕐

Timestamp

Exact time the block was created

💳

Transactions

The actual data — who sent what to whom

🔗

Previous Hash

Hash of the block before — this creates the "chain"

🎲

Nonce

"Number used once" — the miner changes this during mining

🔐

Hash

Unique digital fingerprint of ALL the above data combined

The critical field: Previous Hash. This is what links blocks together into a chain. Block #5's "Previous Hash" field contains the hash of Block #4. Block #4 contains the hash of Block #3, and so on, all the way back to the Genesis Block (block #0). If anyone changes Block #3's data, its hash changes, which means Block #4's "Previous Hash" no longer matches — breaking the entire chain from that point forward.
What is SHA-256 hashing? SHA-256 is a one-way mathematical function that takes any input (a single letter, an entire book) and produces a fixed 64-character hexadecimal string. Even changing one character in the input produces a completely different hash. It's impossible to reverse — you cannot figure out the input from the hash. Try it below:

⛏️ Proof of Work — Mining the Block

The computational race to find a valid hash

The block is assembled, but it can't be added to the chain yet. The miner must prove they did computational work — this is called Proof of Work (PoW). The rule is: the block's hash must start with a certain number of leading zeros. The miner has no shortcut — they must try different nonce values over and over until they find one that produces a hash meeting the target.
Why does this matter? Proof of Work makes it expensive and time-consuming to create a block, but instant to verify one. Any node can hash the block once to check if it's valid. This asymmetry (hard to create, easy to check) is what secures the network. An attacker would need enormous computing power to outpace the honest miners.

🔗 The Complete Blockchain

Your block is now permanently part of the chain

Block confirmed! The majority of the network accepted your block. It is now part of the permanent, immutable blockchain. Every node has updated their copy. The transactions inside are now confirmed and the recipients can spend their funds.
Notice the chain linking: Each block's Previous Hash (blue) matches the Hash (gold) of the block before it. This is what creates the unbreakable chain. The Genesis Block (Block #0) has a previous hash of "0" because there's nothing before it.

🔓 Why You Can't Tamper With a Blockchain

Try it yourself — and learn about the 51% attack

Imagine a fraudster wants to change a past transaction — maybe to take back money they already sent. Try editing the transaction data in any block below, then click "Validate Chain" to see what happens.
Why tampering fails — step by step:
1. The attacker changes data in Block #2.
2. Block #2's hash changes (because the data changed).
3. Block #3 still stores the old hash of Block #2 as its "Previous Hash" — mismatch!
4. The attacker would need to re-mine Block #3 (find a new valid nonce), but then Block #4 breaks too.
5. They'd need to re-mine every single block after the tampered one.
6. While doing this, honest miners are still adding new blocks. The attacker can never catch up unless they control more computing power than the entire rest of the network.
The 51% Attack — the only theoretical weakness:

If a single entity controlled more than 50% of the network's computing power, they could theoretically create a longer chain faster than the honest miners and trick the network into accepting their tampered version.

In practice, a 51% attack is virtually impossible on large blockchains like Bitcoin. The network has so much computing power that gaining majority control would cost billions of pounds in hardware and electricity — far more than any potential gain. This economic disincentive is part of the security model.

📜 Smart Contracts

Self-executing code stored on the blockchain

A smart contract is a small program stored on the blockchain that automatically executes when predefined conditions are met. Think of it as an "if-then" agreement that runs itself — no lawyers, no banks, no middlemen needed.

📄 Traditional Contract

Written in English. Requires lawyers to interpret. Enforced by courts (slow, expensive). Either party can break the agreement.

📜 Smart Contract

Written in code. Executes automatically. Enforced by the blockchain (instant, trustless). Cannot be broken or altered once deployed.

Real-world examples of smart contracts:
• Insurance: Flight delayed by 2+ hours? The contract automatically pays your claim.
• Supply chain: Package scanned at destination? Payment automatically released to the supplier.
• Gaming: You win the match? Prize tokens are automatically sent to your wallet.
• Crowdfunding: Target amount reached by deadline? Funds released to the project. If not? Everyone is automatically refunded.

Try a simulated smart contract — an escrow agreement:

// Escrow: Buyer pays, goods confirmed, seller receives payment
contract Escrow {
  buyer  = "Alice"
  seller = "Bob"
  amount = 100 coins
  status = "AWAITING_PAYMENT"

  function deposit() {
    // Buyer sends funds to contract
    if (msg.sender == buyer) → hold funds
  }

  function confirmDelivery() {
    // Buyer confirms goods received
    if (msg.sender == buyer) → send funds to seller
  }
}

Key point: Smart contracts are stored on the blockchain, so they are immutable and transparent. Once deployed, nobody (not even the creator) can change the rules. Both parties can read the code and verify exactly what will happen. The contract executes automatically — there's no way for either party to cheat.
Blockchains that support smart contracts: Ethereum is the most well-known, using a language called Solidity. Others include Cardano, Solana, and Polkadot. Bitcoin's blockchain is mainly for simple transactions and doesn't support complex smart contracts.

🎓 Complete Summary

The full lifecycle of a block — everything in one place

You've now walked through every stage of how a block is created and added to a blockchain. Here's the complete process:
1
Transaction Created & Signed

A user creates a transaction (e.g. "Alice sends 50 coins to Bob") and signs it with their private key. The transaction is broadcast to the peer-to-peer network via gossip protocol.

2
Transaction Enters the Mempool

Nodes validate the transaction (correct signature, sufficient funds) and place it in their mempool — a waiting area of unconfirmed transactions.

3
Miner Builds a Candidate Block

A miner selects transactions from the mempool (usually prioritising higher fees) and assembles them into a block with: index, timestamp, transactions, previous hash, and nonce.

4
Proof of Work — Mining

The miner repeatedly changes the nonce and hashes the entire block using SHA-256, trying to find a hash that starts with the required number of leading zeros (the difficulty target). This takes enormous computational effort but is trivial to verify.

5
Block Broadcast to Network

The miner broadcasts the completed block to all nodes. Each node independently verifies: valid transactions, correct previous hash, valid proof of work, and compliance with all protocol rules.

6
Consensus — Majority Accepts

If more than 50% of the network's nodes validate and accept the block, it achieves consensus. It becomes the agreed-upon truth. The miner receives a block reward (newly created coins + transaction fees).

7
Block Added Permanently to Chain

Every node appends the block to their copy of the blockchain. The transactions are now confirmed and immutable. The block's hash will be stored as "Previous Hash" in the next block, extending the unbreakable chain. Tampering with any block would require re-mining every subsequent block while outpacing the entire network — which is computationally infeasible.

Key exam vocabulary:
• Block — a container of transaction data linked to the previous block
• Hash — a fixed-length digital fingerprint produced by a one-way function (SHA-256)
• Nonce — "number used once" — the value miners change to find a valid hash
• Proof of Work — the process of finding a nonce that produces a hash meeting the difficulty target
• Consensus — agreement among more than 50% of nodes that a block is valid
• Mempool — the pool of unconfirmed transactions waiting to be included in a block
• Genesis Block — the very first block in a blockchain (index 0)
• 51% Attack — a theoretical attack where one entity controls majority computing power
• Immutable — cannot be changed after being written
• Decentralised — no single point of control; distributed across many nodes
• Smart Contract — self-executing program stored on the blockchain
• Distributed Ledger — a database shared and synchronised across multiple nodes
