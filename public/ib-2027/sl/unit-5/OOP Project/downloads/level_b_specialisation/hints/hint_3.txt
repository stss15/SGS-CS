=== HINT 3: Structure and Pattern ===

Here's the structure—you fill in the logic:

---------------------------------------------
BRUTE CLASS
---------------------------------------------
- Create a Brute class that inherits from Player
- In __init__, call the parent constructor first
- Override stats: higher health and armour, lower accuracy
- Add describe_specialty() that returns a Brute description

---------------------------------------------
SCOUT CLASS
---------------------------------------------
- Create a Scout class that inherits from Player
- In __init__, call the parent constructor first
- Override stats: lower health and armour, higher accuracy
- Add describe_specialty() that returns a Scout description

---------------------------------------------
WHY THIS WORKS
---------------------------------------------

1. Both classes INHERIT from Player
   → They automatically have get_status(), take_damage(), heal()
   → You don't need to rewrite those methods!

2. super().__init__(name) runs Player's __init__
   → Sets up self.name and default values

3. After super(), you OVERRIDE specific attributes
   → This is called "specialisation"

---------------------------------------------
COMMON MISTAKES
---------------------------------------------

✗ Forgetting to import Player:
    Make sure Player is imported at the top of player_types.py

✗ Forgetting (Player) after the class name:
    Brute and Scout must inherit from Player

✗ Forgetting super().__init__(name):
    → The name won't be set!
