Choosing the Right Test Data

Quick Recall (7.6)

Range, Length, Type, Presence, Format, Check Digit

The Big Question

Why do car companies crash their own cars?

❌ It’s not to destroy them.

They run crash tests to find weaknesses before real people get hurt.

✅ Same with software: we test with different data to make sure programs work in all situations.

Normal inputs, extreme edges, and invalid cases.

Four types of test data

Types of Test Data

Normal Data

Typical, expected data

Abnormal Data

Data that should be rejected

Extreme Data

At the very edges of valid

Boundary Data

Right at the boundary

Did You Know?

Many Bugs Live at the Edges

“Off‑by‑one” mistakes often happen near boundaries (e.g., 0 vs 1, last item in a list).

That’s why boundary data is so important.

Testing Needs Expected Results

Good tests include the input and what output you expect.

Then you can tell if the program behaves correctly.

Let's Use an Example

A program accepts exam marks from 0 to 100

INPUT Mark
IF Mark >= 0 AND Mark <= 100 THEN
    OUTPUT "Valid mark"
ELSE
    OUTPUT "Invalid mark"
ENDIF

What test data should we use to test this properly?

Normal Data

Typical data that should be accepted

Definition

Normal data is typical, sensible data that the program should accept and process correctly.

Examples (0-100)

45

73

50

All within the valid range

Abnormal Data

Data that should be rejected

Definition

Abnormal data (also called erroneous data) is data the program should NOT accept.

The program should reject it without crashing!

Examples (0-100)

-5 (below range)

150 (above range)

"fifty" (wrong type)

Extreme Data

Data at the edges of valid range (but still valid)

Definition

Extreme data is at the very limits of what's accepted.

Tests the edges of your validation.

Examples (0-100)

0 (minimum valid)

100 (maximum valid)

Both should be accepted!

Boundary Data

Data right at the boundary between valid and invalid

Definition

Boundary data tests the exact point where data changes from valid to invalid.

Always test in pairs: one that passes, one that fails.

Examples (0-100)

Lower boundary:

-1 (just below)

0 (just passes)

Upper boundary:

100 (just passes)

101 (just above)

Extreme vs Boundary (R-Stack)

Extreme Data

The smallest and largest valid values.

Example (0–100): 0 and 100

Boundary Data

Values right around the edge: one valid and one invalid.

Example (0–100): -1/0 and 100/101

Extreme: 0, 100 (still valid)

Boundary: -1/0 and 100/101 (pair around the limit)

Quick Check

Which pair is boundary data for a valid range of 0–100?

A. 0 and 100

B. -1 and 0

C. 45 and 73

Answer: B (and similarly 100/101 at the top boundary).

Quick Check

Which values are extreme data for a valid range of 0–100?

A. 0 and 100

B. -1 and 0

C. 101 and 150

Answer: A

True or False?

Check Your Understanding

  1. Extreme data should be rejected by the program.
  2. Boundary data tests values at the very edge of valid and invalid.
  3. You only need to test with normal data.

Press Down to reveal answers

Question 1

Extreme data should be rejected by the program.

Answer: FALSE

Extreme data is at the edges but still valid. It should be accepted!

Question 2

Boundary data tests values at the very edge of valid and invalid.

Answer: TRUE

Boundary data tests the exact point where data goes from valid to invalid (both sides of the boundary).

Question 3

You only need to test with normal data.

Answer: FALSE

You need to test with all four types: normal, abnormal, extreme, and boundary data to test thoroughly.

Key Takeaways

✅ Normal = typical data that should be accepted

❌ Abnormal = data that should be rejected

🟧 Extreme = min/max valid values

🟪 Boundary = values around the edge (valid + invalid pair)
