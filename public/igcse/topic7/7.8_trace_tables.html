The Big Question

How do you find a bug when the code "looks right"?

Sometimes code seems perfect… but still gives the wrong answer.

That usually means a logic error.

✅ Think like a computer: execute it step by step.

This is a dry run, recorded in a trace table.

What is a trace table?

What is a Trace Table?

Definition: A table used to record the values of variables as an algorithm is executed, step by step.

Structure

One column per variable

Plus an OUTPUT column

One row per change

Purpose

Track how values change

Find logic errors

Understand algorithm flow

Did You Know?

Loops Hide Lots of Mistakes

Loops repeat logic many times, so a small error can create a big wrong result.

Trace tables make each repetition visible.

Great for Logic Errors

Trace tables won’t fix syntax errors, but they help you spot where the logic goes wrong.

They’re a key debugging tool in exams.

Tracing Loops

This is where trace tables really shine!

Total ← 0
FOR Count ← 1 TO 3
    Total ← Total + Count
NEXT Count
OUTPUT Total
Watch each iteration

Tracing the Loop

Total ← 0
FOR Count ← 1 TO 3
    Total ← Total + Count
NEXT Count
OUTPUT Total
Count Total OUTPUT
0
1 1
2 3
3 6
3 6 6

Logic: Total = 0 + 1 + 2 + 3 = 6

Trace Table Golden Rules

  1. One column per variable – plus OUTPUT
  2. New row only when a value changes
  3. Execute in order – line by line
  4. Show your working – especially in loops
  5. Don't skip steps – even if it seems obvious

Quick Check

When do you add a new row in a trace table?

When a value changes (not automatically on every line).

A Bigger Example

True or False?

Check Your Understanding

  1. A trace table should have one column for each variable.
  2. You add a new row every line of code.
  3. Trace tables are only useful for finding syntax errors.

Press Down to reveal answers

Question 1

A trace table should have one column for each variable.

Answer: TRUE

Each variable gets its own column, plus an OUTPUT column to record any outputs.

Question 2

You add a new row every line of code.

Answer: FALSE

You add a new row only when a value changes, not for every line of code.

Question 3

Trace tables are only useful for finding syntax errors.

Answer: FALSE

Trace tables are used to find logic errors – when code runs but produces wrong results. Syntax errors stop code from running at all!

Key Takeaways

🧾 A trace table records variable values as code runs

📝 A dry run = executing the algorithm manually

📊 One column per variable (+ OUTPUT)

✅ Add a new row when a value changes
