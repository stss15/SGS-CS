# AI Agent Content Writing Guide

> Note: This document covers content style guidance. For build/process instructions, start with `docs/agent/AGENT_GUIDE.md`.

> **Purpose:** This document defines how to write educational content for students at different levels. It specifies the language, tone, complexity, vocabulary, and pedagogical approach for each curriculum: **KS3** (Years 7-9), **IGCSE** (Years 10-11), and **IB** (Years 12-13).

---

## Quick Reference Matrix

| Aspect | KS3 (Years 7-9) | IGCSE (Years 10-11) | IB (Years 12-13) |
|--------|-----------------|---------------------|------------------|
| **Reading Age** | 11-14 years | 14-16 years | 16-18 years |
| **Sentence Length** | Short (8-15 words) | Medium (12-20 words) | Variable (15-25 words) |
| **Vocabulary** | Everyday + scaffolded technical | Technical with definitions | Academic + technical fluency |
| **Abstraction Level** | Concrete → Abstract | Abstract with examples | Abstract reasoning expected |
| **Question Style** | "What is...?", "How does...?" | "Explain...", "Describe..." | "Evaluate...", "Analyse...", "To what extent..." |
| **Analogies** | Essential (everyday objects) | Helpful (real-world systems) | Optional (assume prior knowledge) |
| **Prior Knowledge** | Assume none | Assume KS3 foundations | Assume IGCSE mastery |
| **Exam Focus** | None (skills-based) | Exam technique important | Exam command terms critical |

## Part 1: KS3 Content (Years 7-9)

### 1.1 Student Profile

**Who are KS3 students?**
- Ages 11-14 (Year 7 = 11-12, Year 8 = 12-13, Year 9 = 13-14)
- Many are new to formal Computer Science education
- Diverse prior experience (some have coded at home, others haven't)
- Short attention spans; need variety and movement
- Respond well to games, challenges, and immediate feedback
- Developing abstract thinking; still need concrete examples
- May struggle with technical vocabulary without scaffolding

### 1.2 Language Guidelines

#### Sentence Structure
- **Keep sentences short:** 8-15 words maximum
- **One idea per sentence:** Never compound complex ideas
- **Active voice:** "The computer stores data" not "Data is stored by the computer"
- **Present tense:** "The CPU processes instructions" not "The CPU will process instructions"

#### Vocabulary Rules

**DO use:**
- Everyday words first, then introduce technical terms
- Dual-coding: "The CPU (the 'brain' of the computer) processes instructions"
- Consistent terminology throughout a unit

**DON'T use:**
- Jargon without immediate explanation
- Latin/Greek roots without breakdown
- Acronyms without expansion
- Abstract nouns without concrete examples

#### Example Transformations

❌ **Too complex:**
> "The fetch-execute cycle is the fundamental operational process by which a central processing unit retrieves program instructions from memory, decodes them, and subsequently executes the appropriate operations."

✅ **KS3 appropriate:**
> "Every second, the CPU does three things: it fetches (gets) an instruction, decodes (reads) it, and executes (does) it. This happens millions of times per second!"

### 1.3 Tone and Voice

- **Encouraging:** "Great question!", "Let's explore this together"
- **Inclusive:** "We all leave digital footprints", "You might have noticed..."
- **Curious:** Frame content as discovery, not instruction
- **Supportive:** Acknowledge difficulty, normalise mistakes

**Phrases to use:**
- "Have you ever wondered...?"
- "Imagine you're a..."
- "Think about the last time you..."
- "What do you think would happen if...?"

**Phrases to avoid:**
- "Obviously..." (nothing is obvious to a beginner)
- "Simply..." (implies it should be easy)
- "You should already know..." (creates anxiety)
- "It's just like..." (without explaining the connection)

### 1.4 Pedagogical Approach

#### Structure Every Lesson As:
1. **Hook** (The Big Question) — Create curiosity
2. **Recall** — Activate prior knowledge (5 quick questions)
3. **Concepts & Skills** — What are we learning today?
4. **Keywords** — 5 terms with simple definitions
5. **Mini Task** — Short interactive activity
6. **Main Task** — Core learning activity
7. **Plenary** — Reflection and misconception check

#### Scaffolding Techniques

1. **I Do, We Do, You Do:**
   - Model the skill explicitly
   - Practice together with the class
   - Independent practice with support available

2. **Sentence Starters:**
   - "A digital footprint is..."
   - "One example of personal data is..."
   - "The difference between public and private data is..."

3. **Visual Supports:**
   - Icons for every keyword
   - Diagrams before text explanations
   - Colour-coding for categories

### 1.5 Content Depth

#### What to Include:
- Real-world examples from students' lives (social media, games, phones)
- Ethical discussions (simplified): right vs wrong, safety
- Hands-on activities: sorting, matching, creating
- Immediate relevance: "Why does this matter to ME?"

#### What to Exclude:
- Historical context (unless directly relevant)
- Mathematical proofs or complex calculations
- Detailed specifications or standards
- Edge cases or exceptions

### 1.6 Assessment Language

**Question stems for KS3:**
- "What is...?" (recall)
- "Give an example of..." (application)
- "Sort these into..." (classification)
- "Match the... to the..." (connection)
- "Why might... be a problem?" (evaluation - scaffolded)

**Avoid:**
- "Evaluate the extent to which..."
- "Critically analyse..."
- "Compare and contrast the efficiency of..."

## Part 2: IGCSE Content (Years 10-11)

### 2.1 Student Profile

**Who are IGCSE students?**
- Ages 14-16 (Year 10 = 14-15, Year 11 = 15-16)
- Completing a formal qualification (Cambridge IGCSE 0478/0984)
- Mixed ability with some strong programmers and some weaker students
- External exam pressure; need exam technique
- Can handle abstraction with support
- Need explicit links between concepts
- Preparing for A-Level/IB (consider progression)

### 2.2 Language Guidelines

#### Sentence Structure
- **Medium length:** 12-20 words typical
- **Can handle compound sentences:** "The CPU fetches the instruction, and then it decodes the opcode"
- **Technical precision required:** Use exact syllabus terminology
- **Passive voice acceptable** when describing processes

#### Vocabulary Rules

**DO use:**
- Technical terms from the syllabus specification
- Definitions that match mark scheme wording
- Consistent terminology across the course
- Keywords highlighted and defined (red click-to-define system)

**DON'T use:**
- Colloquialisms in formal definitions
- Simplified terms when exam uses technical ones
- Multiple terms for the same concept

#### Example Transformations

❌ **Too simple (KS3 level):**
> "RAM is like your desk — it's where you put things you're working on right now."

✅ **IGCSE appropriate:**
> "RAM (Random Access Memory) is volatile primary storage that temporarily stores data and instructions currently in use by the CPU. Unlike ROM, RAM contents are lost when power is removed."

### 2.3 Tone and Voice

- **Academic but accessible:** Formal content, friendly delivery
- **Exam-focused:** "This is a common exam question", "The mark scheme requires..."
- **Precise:** No ambiguity in definitions
- **Supportive:** "This is a tricky concept, let's break it down"

**Phrases to use:**
- "The key points to remember are..."
- "A common mistake is thinking..."
- "The exam often asks you to..."
- "Make sure you can explain..."

### 2.4 Pedagogical Approach

#### Structure Every Lesson As:
1. **Retrieval Practice** — 3-5 questions from previous topics
2. **The Hook** — Why does this matter? Real-world connection
3. **Key Terms** — Formal definitions (exam-ready)
4. **Concept Introduction** — Question-first, then explanation
5. **Deep Dive** — Vertical slides for complex processes
6. **Worked Examples** — Step-by-step demonstrations
7. **Misconception Check** — True/False with explanations
8. **Exam-Style Practice** — Actual exam questions

#### Key Techniques

1. **Question-First Approach:**
   - Never start with a definition
   - Pose a puzzle or scenario
   - Let students speculate
   - Then reveal the concept as the solution

2. **Analogies with Limits:**
   - Use analogies to introduce concepts
   - But also explain where they break down
   - "RAM is like a desk workspace... but unlike a desk, RAM is completely erased when power is lost"

3. **Process Breakdown:**
   - Use vertical slides for multi-step processes
   - Fragment reveals for each step
   - Show diagrams first, then trace through

### 2.5 Content Depth

#### What to Include:
- All syllabus specification points (verbatim coverage)
- Mark scheme language and keywords
- Common exam questions and approaches
- Practical examples from industry
- Links between topics ("This connects to what we learned about...")

#### What to Exclude:
- Content beyond syllabus scope (unless clearly flagged as extension)
- Historical details unless specified
- Implementation details beyond specification
- Alternative approaches not in syllabus

### 2.6 Exam Command Terms

Train students to respond to these IGCSE command words:

| Command | What it means | Marks typically |
|---------|---------------|-----------------|
| **State** | Give a brief answer | 1 mark |
| **Identify** | Name or recognise | 1 mark |
| **Describe** | Give characteristics/features | 2-3 marks |
| **Explain** | Give reasons/how/why | 2-4 marks |
| **Compare** | Identify similarities and differences | 2-4 marks |
| **Discuss** | Consider different views/aspects | 4-6 marks |

### 2.7 Assessment Language

**Question stems for IGCSE:**
- "State two characteristics of..." (recall)
- "Describe how..." (process understanding)
- "Explain why... is used" (reasoning)
- "Compare RAM and ROM" (analysis)
- "Give one advantage and one disadvantage of..." (evaluation)

## Part 3: IB Content (Years 12-13)

### 3.1 Student Profile

**Who are IB students?**
- Ages 16-18 (Year 12 = 16-17, Year 13 = 17-18)
- Completing IB Diploma (SL or HL)
- High academic ability and motivation
- Can handle abstract reasoning
- Expected to make connections independently
- Preparing for university-level study
- Internal Assessment (IA) requires independent research skills

### 3.2 Language Guidelines

#### Sentence Structure
- **Variable length:** Can handle complex, nuanced sentences
- **Academic register:** Formal, precise, referenced
- **Conditional reasoning:** "If... then... however..."
- **Hedging language:** "This may indicate...", "Research suggests..."

#### Vocabulary Rules

**DO use:**
- Full technical vocabulary without over-explanation
- Syllabus-specific command terms
- Industry-standard terminology
- Academic discourse markers ("Furthermore", "In contrast", "Consequently")

**Assume students can:**
- Define basic computing terms from prior study
- Parse compound technical sentences
- Infer meaning from context
- Research unfamiliar terms independently

#### Example Transformations

❌ **Too simple (IGCSE level):**
> "Recursion is when a function calls itself. It's useful for solving problems that can be broken into smaller versions of the same problem."

✅ **IB appropriate:**
> "Recursion is a programming paradigm where a function invokes itself with modified parameters, progressing toward a base case that terminates the recursive chain. Recursive solutions often provide elegant implementations for inherently recursive structures (trees, graphs) and divide-and-conquer algorithms, though they may incur stack overhead compared to iterative alternatives."

### 3.3 Tone and Voice

- **Scholarly:** University-preparatory academic register
- **Challenging:** "Consider the implications...", "Critically evaluate..."
- **Nuanced:** Acknowledge complexity and trade-offs
- **Autonomous:** Encourage independent investigation

**Phrases to use:**
- "Evaluate the extent to which..."
- "Consider the trade-offs between..."
- "From a computational thinking perspective..."
- "This connects to the broader concept of..."
- "The implications for [ethics/society/efficiency] include..."

### 3.4 Pedagogical Approach

#### Structure Every Lesson As:
1. **Retrieval Practice** — Interleaved questions from multiple topics
2. **Conceptual Hook** — Abstract question or paradox
3. **Theory Introduction** — Formal definitions and principles
4. **Worked Examples** — Complex, multi-step problems
5. **Code Analysis** — Trace, predict, debug
6. **Application** — Novel problems requiring transfer
7. **Extension** — Links to HL content or further reading
8. **Exam Practice** — Past paper questions with mark schemes

#### Key Techniques

1. **Conceptual Connections:**
   - Explicitly link topics: "This is an example of abstraction, which we saw in..."
   - Cross-reference syllabus strands
   - Build towards synoptic understanding

2. **Exam Command Terms (IB-specific):**

| Command | What it means | Depth required |
|---------|---------------|----------------|
| **Define** | Give precise meaning | Brief, exact |
| **Outline** | Give brief account | Key features only |
| **Describe** | Give detailed account | Characteristics, not reasons |
| **Explain** | Give detailed account with reasons | How and why |
| **Analyse** | Break down to identify components and relationships | Structure and connections |
| **Evaluate** | Make judgement by weighing evidence | Balanced conclusion |
| **Discuss** | Offer balanced review with range of arguments | Multiple perspectives |
| **Compare** | Give account of similarities and differences | Reference to both |
| **Compare and Contrast** | As above, with explicit differences | Both similarities and differences |
| **To what extent** | Consider merits/limitations | Conclude with degree statement |

3. **Thinking Skills Integration:**
   - Abstract thinking
   - Pattern generalisation
   - Algorithm design
   - Computational complexity analysis
   - Ethical reasoning

### 3.5 Content Depth

#### What to Include:
- Full syllabus coverage (SL and HL as appropriate)
- Algorithm efficiency analysis (Big O notation)
- Pseudocode and multiple language implementations
- Past paper questions with examiner reports
- IA connection points
- Extended reading references
- Ethical and societal implications (ATL skills)

#### HL vs SL Differentiation

For HL students:
- Additional depth on core topics
- Recursive thinking
- OOP principles and design patterns
- Complex data structures (trees, graphs)
- More sophisticated algorithm analysis

### 3.6 Assessment Language

**Question stems for IB:**
- "Outline the characteristics of..." (describe briefly)
- "Explain how a binary search tree maintains sorted order" (process with reasoning)
- "Analyse the time complexity of..." (break down and evaluate)
- "Evaluate the use of recursion vs iteration for..." (judgement with evidence)
- "To what extent does abstraction simplify..." (balanced conclusion)
- "Discuss the ethical implications of..." (multiple perspectives)

## Part 4: Cross-Curriculum Guidelines

### 4.1 Universal Pedagogical Principles

These apply at ALL levels:

1. **Question-First Approach**
   - Never start with a definition
   - Create cognitive dissonance or curiosity
   - Let students predict before revealing

2. **Misconception Targeting**
   - Identify common misconceptions for each topic
   - Explicitly address them with True/False checks
   - Explain WHY the misconception is wrong

3. **Progressive Disclosure**
   - Use fragments/reveals to control information flow
   - One idea per reveal
   - Build complexity step-by-step

4. **Spaced Retrieval**
   - Every lesson starts with retrieval practice
   - Mix questions from recent and distant topics
   - Low-stakes, immediate feedback

5. **Visual-First Explanations**
   - Diagrams before text
   - Icons for concepts
   - Colour-coding for categories

### 4.2 Adapting Content Between Levels

When the same topic appears at multiple levels:

| Topic | KS3 | IGCSE | IB |
|-------|-----|-------|-----|
| **Binary** | "Computers only understand 1s and 0s" | "Binary uses base-2 positional notation" | "Binary representation enables direct mapping to transistor states" |
| **Networks** | "How do devices talk to each other?" | "LANs use switches and routers to direct packets" | "Analyse the efficiency trade-offs of circuit vs packet switching" |
| **Data Types** | "Different types of data" | "Integer, Real, Boolean, Char, String" | "Type systems enable compile-time error detection and memory optimisation" |

### 4.3 Accessibility Considerations

Apply at all levels:

- **ADHD:** Short sections, timers for tasks, movement opportunities
- **Dyslexia:** Sans-serif fonts, dual-coded icons, Immersive Reader compatible
- **EAL:** Pre-teach keywords, image-led examples, sentence starters
- **Visual impairment:** Alt text for images, sufficient colour contrast
- **Low prior knowledge:** Entry point scaffolding, "low floor" tasks

### 4.4 Differentiation Within Levels

Every level should offer:
- **Low Floor:** Entry point accessible to weakest students
- **High Ceiling:** Extension for most able students

**KS3 Example:**
- Low floor: Sort 10 items into Public/Private categories
- High ceiling: Analyse a real privacy policy and identify 3 data practices

**IGCSE Example:**
- Low floor: State two advantages of using a database
- High ceiling: Design a normalised database schema for a given scenario

**IB Example:**
- Low floor: Trace the execution of a given recursive function
- High ceiling: Design and analyse a recursive solution to a novel problem

## Part 5: Content Templates

### 5.1 Keyword Definition Template

**KS3:**
```
[KEYWORD] — [Simple definition in 10-15 words using everyday language]
Example: Password — A secret word or phrase that only you know, used to log in.
```

**IGCSE:**
```
[KEYWORD] — [Precise definition matching syllabus/mark scheme language]
Example: Primary Storage — Memory directly accessible by the CPU, including RAM and ROM.
```

**IB:**
```
[KEYWORD] — [Formal definition with technical precision]
Example: Abstraction — The computational thinking skill of reducing complexity by hiding irrelevant details while retaining essential characteristics.
```

### 5.2 Explanation Template

**KS3 Pattern:**
1. Relatable scenario from student's life
2. Simple question: "Have you ever noticed...?"
3. Core concept in 1-2 short sentences
4. Analogy using everyday object
5. Quick check: "So, in your own words..."

**IGCSE Pattern:**
1. Question-first hook
2. Key term with formal definition
3. Analogy (with limitations noted)
4. Step-by-step process explanation
5. Worked example
6. Common misconception addressed
7. Exam-style question practice

**IB Pattern:**
1. Conceptual question or paradox
2. Formal definition with context
3. Connection to prior learning
4. Algorithm/implementation details
5. Complexity analysis (if applicable)
6. Trade-offs and alternatives discussed
7. Ethical/societal implications
8. Past paper question with mark scheme reference

### 5.3 Assessment Question Template

**KS3:**
```
Q: What is a [KEYWORD]?
A: [Simple 1-sentence definition]

Q: Give ONE example of [CONCEPT].
A: [Concrete example from student's world]

Q: TRUE or FALSE: [Misconception statement]
A: [TRUE/FALSE] because [simple reason]
```

**IGCSE:**
```
Q: Describe how [PROCESS] works. [3 marks]
A: 
- [First step/feature] [1]
- [Second step/feature] [1]
- [Third step/feature] [1]

Q: Explain why [CONCEPT] is used in [CONTEXT]. [2 marks]
A: [Reason 1] [1], which means [Benefit/Outcome] [1]
```

**IB:**
```
Q: Outline [CONCEPT]. [2 marks]
A: [Brief, precise definition covering key characteristics]

Q: Analyse the [APPROACH] used in [SCENARIO]. [4 marks]
A: 
- [Component identification] [1]
- [Relationship explanation] [1]
- [Strength/advantage] [1]
- [Limitation/trade-off] [1]

Q: To what extent does [CONCEPT] address [PROBLEM]? [6 marks]
A:
- [Definition/context] [1]
- [Arguments for] [2]
- [Arguments against/limitations] [2]
- [Balanced conclusion with degree statement] [1]
```

## Part 6: Checklists for AI Agents

### Before Writing Any Content:

- [ ] Identified the target level (KS3/IGCSE/IB)
- [ ] Checked the syllabus/specification for required coverage
- [ ] Listed key vocabulary with level-appropriate definitions
- [ ] Identified common misconceptions to address
- [ ] Planned the question-first hook

### KS3 Content Checklist:

- [ ] Sentences average 8-15 words
- [ ] No unexplained technical jargon
- [ ] Every keyword has an everyday analogy
- [ ] Content connects to students' daily lives
- [ ] Activities are interactive (sort, match, create)
- [ ] Tone is encouraging and inclusive
- [ ] Low floor AND high ceiling options included

### IGCSE Content Checklist:

- [ ] Uses exact syllabus terminology
- [ ] Definitions match mark scheme wording
- [ ] Processes are broken into steps
- [ ] Misconceptions explicitly addressed
- [ ] Exam command terms used appropriately
- [ ] Links to other topics made explicit
- [ ] Retrieval practice from previous topics included

### IB Content Checklist:

- [ ] Academic register throughout
- [ ] IB command terms used correctly
- [ ] Algorithm analysis included where appropriate
- [ ] Ethical/societal implications discussed
- [ ] HL extensions clearly marked (if applicable)
- [ ] Past paper references included
- [ ] Connections to IA opportunities noted

## Part 7: Example Comparisons

### Topic: Variables in Programming

**KS3 Version:**
> A **variable** is like a labelled box where you store information. You give the box a name (like "score" or "playerName") and put something inside it. Later, you can look at what's in the box or change it.
>
> **Think of it like this:** If you have a box labelled "Age" with the number 12 inside, you can check what's in it (12) or update it when you have a birthday (13).

**IGCSE Version:**
> A **variable** is a named memory location that stores a value which can be changed during program execution. Each variable has:
> - A **name** (identifier) that follows naming conventions
> - A **data type** that defines what kind of data it stores
> - A **value** that can be read or updated
>
> Example: `score = 0` creates an integer variable called "score" with an initial value of 0.

**IB Version:**
> A **variable** is an abstraction representing a named memory location whose contents may change during program execution. Variables provide a level of indirection between the programmer and physical memory addresses, enabling readable code and facilitating memory management.
>
> Key considerations:
> - **Scope** determines where a variable is accessible (local vs global)
> - **Lifetime** defines when memory is allocated and deallocated
> - **Type** constrains the operations that can be performed
>
> Static typing (Java, Python with type hints) enables compile-time error detection, while dynamic typing provides flexibility at the cost of runtime type errors.

## Summary

| Level | Core Principle |
|-------|----------------|
| **KS3** | Make it relatable, concrete, and encouraging |
| **IGCSE** | Make it precise, exam-ready, and well-scaffolded |
| **IB** | Make it rigorous, analytical, and interconnected |

When in doubt:
- **KS3:** "Would my 11-year-old cousin understand this?"
- **IGCSE:** "Would this get full marks on the exam?"
- **IB:** "Would this prepare a student for university Computer Science?"
