# Migration

The migration plan is phased and parity-driven. The goal is not to rename everything at once; it is to remove duplication without losing any content or route behavior.

## Phases

1. Shared shell and token consolidation
2. Reader, textbook, curriculum index, and unit plan migration
3. Assessment and flashcard consolidation
4. Slide deck normalization
5. Interactive tool and simulation consolidation
6. Downloadable asset ownership and manifesting
7. Legacy removal once parity is complete

## Gate Rules

- Preserve exact public URLs and aliases.
- Preserve section order and unit structure.
- Preserve downloadable assets.
- Preserve route coverage for textbooks, slides, assessments, flashcards, and tools.

## Exit Criteria

- Typed route and content manifests exist.
- Shared shells are implemented once.
- Legacy passthroughs are no longer needed for any active route family.
- Browser parity checks pass for the important route set.

See [phases.md](phases.md) for a compact execution order.
