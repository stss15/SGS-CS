## Template Duplication Notes

- No `.njk` and `.html` files share the same base path under `src/pages`; duplication is mostly between `src/pages` (sources) and `public` (build output).
- The 20 `layouts/arcade.njk` pages (IB topics and IGCSE topics) repeat similar `cards` and `resources` lists, differing mostly by topic slug and titles.
- `layouts/unit-plan.njk` is used 23 times with similar data blocks; content is unique but could be driven by structured data if needed.
- Arcade topic metadata (titles, breadcrumbs, hero, cards/resources) are now centralized in `src/data/topics.json` and referenced via `topicKey`.
- IB 2027 unit index pages now use `layouts/arcade.njk` with data-driven cards/resources instead of duplicated HTML markup.
- Arcade pages now default to `css/resource-style.css` when `extraStyles` is omitted.

## Consolidation Opportunities

- Keep manual-response tests on the shared exam runtime and extend its config schema when new exam pages are added.
- Fold assessment menu styling into `css/assessment-base.css` when safe; menu pages already share `css/assessments-igcse-menu.css`.
- Extract a deck-base stylesheet consumed by `slide-deck.css`, `ks3-deck.css`, and `igcse-deck.css` to reduce drift.
- Define a clear namespace for stand-alone apps (for example, `public/apps/`) and document them as exceptions to shared asset reuse.
- Move `layouts/arcade.njk` page data into `src/data/` (for example, `igcse-topics.json`, `ib-topics.json`) and render with a single topic template to reduce repeated front matter.

## Risks

- Asset sprawl: adding a new topic currently adds multiple CSS/JS files, making global styling or behavior changes expensive.
- Mixed ownership: some bundles are compiled/minified and are difficult to refactor without source.
