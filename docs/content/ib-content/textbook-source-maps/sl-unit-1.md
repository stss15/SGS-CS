```text
B1.1.2: Fundamental Concepts
Theory:
 ●​ Abstraction: Used in maps (tube maps), paintings, and OOP (hiding implementation
    details). Reduces complexity, file size, and dev time.
 ●​ Decomposition: Breaks problems down. Correction: It is breaking down the problem,
    not just breaking a program into subroutines (a common student error).
 ●​ Pattern Recognition: Leads to reusable code (functions/libraries) and faster
    development.
 ●​ Algorithmic Design: Creating predictable, sequential steps.
```

## Unit Plan Extract (Context)
```text
Unit Plan: SL Unit 1 - Computational Thinking (B1)
Subject: IB Computer Science (First Assessment 2027)
Grade: Year 12 (SL)
Duration: 2 Weeks (6 Lessons)
Theme: Theme B: Computational Thinking and Problem-solving
Unit Foundation
Concepts The core of this unit is based on Computational Thinking as a problem-solving toolkit. It focuses on the transition from a "wicked," messy real-world problem to a formalised computational model using abstraction (simplification) and decomposition (breaking down).
Content - B1.1.1: Problem specification construction (stakeholders, constraints, inputs/outputs, and success criteria).
	•	B1.1.2/3: The four pillars: Abstraction, Algorithmic Design, Decomposition, and Pattern Recognition. Application to software development, data analysis, and machine learning.
	•	B1.1.4: Flowchart design and tracing using standard symbols.
Skills for Learning Students develop Thinking Skills through critical analysis of scenarios and Communication Skills by translating abstract logic into standardised diagrammatic forms (flowcharts).
Approaches to Teaching - Inquiry-based: Starting with real-world messiness (e.g., an airport check-in) to see why specifications are needed.
	•	Collaborative: Group decomposition challenges to see multiple valid ways to solve the same problem.
	•	Incremental: Moving from natural language to structured algorithms, then to flowcharts.
Terminology Problem Specification, Stakeholder, Problem Statement, Constraints, Evaluation Criteria, Abstraction, Decomposition, Pattern Recognition, Algorithmic Thinking, Flowchart, Trace Table, Dry Run.
Misconceptions - Decomposition: Students often define this as "breaking down a program." It must be understood as breaking down the problem before any code exists.
	•	Abstraction: Misunderstood as "making things complicated." It must be taught as "removing irrelevant detail" to focus on the core logic.
	•	Flowcharts: Forgetting to label decision branches (True/False) or leaving flowlines disconnected.
Adaptive Strategies - Visual Learners: Use physical "Logic Blocks" or cards to represent flowchart symbols before drawing them.
	•	Scaffolded Reasoning: Provide partially completed problem specifications where students only fill in "Constraints" or "Outputs" to reduce cognitive load.
	•	Stretch/Challenge: Provide "Buggy" flowcharts with infinite loops or logic errors for advanced students to debug via trace tables.
TOK Connections - Knowledge & Maps: "The map is not the territory." How does abstraction change our knowledge of the real world? (e.g., the London Tube Map vs. real geography).
	•	Naming as Power: Does naming a problem in a specification "freeze" it into a category that limits our creative solutions?
IBO Learner Profile - Thinkers: Applying critical thinking to solve complex problems through systematic decomposition.
	•	Communicators: Expressing logic through a universal diagrammatic language.
CAS Connections - Service: Developing a problem specification for a local charity’s website or a school club’s database needs.
```
