Unit Plan: SL Unit 12 - The IA Cycle (Criteria A–E)
Subject: IB Computer Science (First Assessment 2027)
Grade: Year 12 (Term 3) & Year 13 (Term 1)
Duration: ~35 Lessons (Approx. 14 Teaching Weeks)
Theme: Theme B: Computational Thinking and Problem-solving
Unit Foundation
Concepts The Internal Assessment (IA) focuses on the Iterative Cycle of software development. It moves beyond simple coding to encompass the full computational thinking process: identifying a human need, designing a robust solution, building complex logic, and critically evaluating the result against measurable success criteria.
Content - Criterion A: Problem specification (measurable requirements) and Stakeholder identification (~300 words).
	•	Criterion B: Planning, decomposition of the problem, and a chronology of steps (GANTT/Agile) (~150 words).
	•	Criterion C: System overview (UML/Flowcharts), UI design, and a comprehensive testing strategy (~150 words).
	•	Criterion D: Development (algorithmic complexity, implementation of data structures) and the 5-minute video demonstration (~1000 words).
	•	Criterion E: Evaluation of success criteria and recommendations for future improvement (~400 words).
	•	Appendices: Full source code and authentication documentation.
Skills for Learning - Self-management Skills: Managing a long-term project across two academic years; breaking down a 2,000-word report into manageable checkpoints.
	•	Thinking Skills: Evaluating choices made during implementation to justify specific algorithmic techniques over others.
	•	Communication Skills: Technical writing that links documentation to the full source code in the appendix.
Approaches to Teaching - Informed by Assessment: Continuous alignment with the IB descriptors (Criterion A-E) to ensure the solution is of sufficient complexity and innovation.
	•	Differentiated (Advisor Role): The teacher acts as a consultant/mentor, providing advice on one draft per criteria without editing the student's work.
	•	Contextualised: Solving a personal, academic, or social environment problem that is significant to the student.
Terminology Solution (Doc + Video), Product (Software only), Stakeholder, Success Criteria, Measurability, Decomposition, GANTT Chart, System Model, Appendix, Screencast, Word Count (2,000 max).
Misconceptions - Documentation vs. Code: Students often mistakenly believe the IA is only about the code. The documentation determines the majority of the marks.
	•	Innovation vs. Templates: Believing that using a pre-existing template (e.g., a simple web template) is acceptable. Innovation and modification must be explicitly documented.
	•	Teacher Debugging: Expecting the teacher to write or debug the source code. Teachers must remain as advisors, not co-developers.
Adaptive Strategies - Executive Function Support: Use of digital project management tools (e.g., Trello or Notion) with pre-set internal deadlines for each Criterion to prevent end-of-unit panic.
	•	Scaffolded Success Criteria: Providing a bank of "measurable verbs" (e.g., "The system shall search and display result in < 2 seconds") to help students write quantifiable Criterion A targets.
	•	Template Checkpoints: Providing structural headers for the report to ensure the word count is distributed correctly across A-E.
TOK Connections - Ethics of Data: What is the developer's responsibility regarding the confidentiality and security of original data collected from stakeholders?
	•	Knowledge Transformation: Does the process of translating a human problem into a code-based solution lose essential nuances of the original context?
IBO Learner Profile - Principled: Ensuring academic integrity through proper citation of third-party libraries and authentication of all code.
	•	Reflective: Evaluating the limitations of the developed system in Criterion E with honesty and critical insight.
CAS Connections - Service: Developing a functional solution for a local charity, school club, or non-profit stakeholder to improve their operational efficiency.
