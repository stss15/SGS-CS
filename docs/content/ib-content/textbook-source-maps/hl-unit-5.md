## Unit Plan Extract (Context)
```text
Unit Plan: HL Unit 5 - Scalable Data Systems (A3.3, A3.4)
Subject: IB Computer Science (First Assessment 2027)
Grade: Year 12 (HL Only)
Duration: 3 Weeks (6 HL Lessons)
Theme: Theme A: Concepts of Computer Science
Unit Foundation
Concepts The focus is on Scalability and Reliability in non-traditional environments. Students move from simple table storage to high-availability systems. Key themes include the ACID vs. BASE trade-off, Consistency in Distributed Systems, and the extraction of value from "Big Data" through OLAP and Data Mining.
Content
	•	A3.3.4-5: Advanced Transaction Management: The ACID properties (Atomicity, Consistency, Isolation, Durability) and Transaction Control Language (COMMIT, ROLLBACK).
	•	A3.3.6: Database Views: Benefits for security, simplicity, and performance.
	•	A3.4.1: Alternative Models: NoSQL (Document, Key-Value, Graph, Columnar) vs. Relational. Cloud and Spatial databases.
	•	A3.4.1: Distributed Databases: Features, fragmentation, replication, and the challenges of consistency.
	•	A3.4.2-3: Data Warehousing: ETL process, Data Mining techniques (Cluster, Classify, Associate), and OLAP (Online Analytical Processing) for Business Intelligence.
Skills for Learning
	•	Thinking Skills: Evaluating when to choose a NoSQL model over a relational one based on schema flexibility and scaling needs.
	•	Research Skills: Investigating the "CAP Theorem" (Consistency, Availability, Partition Tolerance) in modern cloud infrastructures.
Approaches to Teaching
	•	Inquiry-based: Comparing the rigid structure of the "Engineer" table (from A3.pdf) with a JSON-style NoSQL document for the same data.
	•	Case Studies: Analysing real-world platforms (e.g., Netflix or Amazon) to see how distributed databases handle millions of concurrent transactions.
	•	Concept-led: Using the "Library View" analogy—giving a student a list of books they've borrowed without letting them see the fines or addresses of other students.
Terminology
Transaction, ACID, COMMIT, ROLLBACK, View, NoSQL, Schema-less, Cloud Database, Spatial Database, Distributed Database, Replication, Fragmentation, OLAP, Data Warehouse, Data Mining, ETL.
Misconceptions
	•	NoSQL vs. SQL: Believing NoSQL is "better." It is a trade-off: NoSQL offers scaling and flexibility but usually sacrifices strict ACID compliance.
	•	Distributed Consistency: Thinking data is updated everywhere instantly; students must understand "Eventual Consistency."
	•	Data Mining: Confusing it with a standard search. Mining is about discovering unknown patterns, not finding specific records.
Adaptive Strategies
	•	Visual Distributed Systems: Use a "Post-it" board to represent different server nodes. Move data between them to show how replication works and where "Split-brain" scenarios occur.
	•	ACID Checklist: Provide a 4-point card for every scenario—students must explain how the bank transfer satisfies A, C, I, and D.
	•	SQL View Lab: Use a live SQL environment to create a view that masks sensitive columns, then try to query the "hidden" data to see the security in action.
TOK Connections
	•	The Value of Patterns: In Data Mining, we find correlations. Does a correlation between two data points constitute "knowledge" or just a statistical coincidence?
	•	Privacy vs. Intelligence: Does a company's "Business Intelligence" (OLAP) infringe on a consumer's right to remain un-categorised?
IBO Learner Profile
	•	Inquirers: Investigating the underlying logic of distributed ledger technologies (Blockchain) as a form of distributed database.
	•	Knowledgeable: Understanding the technical constraints that drive the move to cloud-based data warehouses.
CAS Connections
	•	Service: Helping a local organisation clean and "mine" their historical data (e.g., donation patterns) to help them better target their community outreach.
```
