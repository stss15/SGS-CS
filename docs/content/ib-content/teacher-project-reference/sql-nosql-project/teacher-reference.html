How to use this guide

Teacher workflow

Open this file locally, then move through the linked lesson pages in order. Each page is written from the teacher perspective: what to teach, what students should produce, the likely questions, and the exact code state to aim for.

What is included

  • Stage-by-stage teacher notes.
  • One implementation page per feature.
  • Inline syntax-highlighted code with the file name above it.
  • Answer keys for the prompts raised on the student side.

What is not included

  • Hosted routes for students.
  • Copy-paste project code for the student site.
  • Every possible extension beyond the supplied task-manager brief.

Teaching note

How the implementation pages are organised

The implementation steps follow the teacher build order you described, not just the current student-roadmap labels.

Build order used in this guide

  1. Problem specification and planning first.
  2. Core SQL schema before any Flask routes.
  3. Database initialisation before the web app queries anything.
  4. HTML shell and interface structure before JavaScript behaviour.
  5. Flask and JavaScript built together, one small function or feature at a time.
  6. Algorithm and database extension only after the core SL build works.
  7. HL theory and JSON practice before the HL backend rebuild.
  8. A separate HL JSON implementation run after the modelling comparison.
  9. A final HL tagging lesson showing how the same algorithm lands differently in JSON.
