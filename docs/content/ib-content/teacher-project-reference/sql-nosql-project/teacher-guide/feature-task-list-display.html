Feature 2: Task list display area

Teacher use on this page

Lesson focus and expected outcome

Use this as the teaching script for the live build. The code blocks show the exact file state to aim for by the end of the step.

What students should finish with

  • The page contains a task list container with a stable identifier.
  • Students can explain why JavaScript needs a named DOM target.
  • The interface still loads cleanly without data.

Questions to ask and the answers you want

Prompt for the class Expected answer / direction
Why add an id here? So JavaScript can reliably find exactly the element it needs to update.
Why create the empty list before writing JavaScript? Because the script needs somewhere to place the rendered rows.
Why is this called a render target? Because it is the part of the page the code will fill with data later.

Teaching notes for this file

  • Use a single clear target such as taskList rather than many tiny scattered targets.
  • Leave it empty for now; the fetch/render lesson will fill it.

How the files link in this lesson

The HTML now exposes a render area. Later the JavaScript will find #taskList, clear it, and append rows based on the data returned from Flask.

Watch for

Common mistakes to stop early

Teacher checks

  • Students naming the element one thing in HTML and another thing later in JavaScript.
  • Using a generic class instead of a unique id when the script needs one exact target.
