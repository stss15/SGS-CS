Implementation step 1

Feature 1: Base HTML shell

Build the page shell first so students understand the document structure before any dynamic behaviour starts.

Teacher onlyExact target state

Teacher use on this page

Lesson focus and expected outcome

Use this as the teaching script for the live build. The code blocks show the exact file state to aim for by the end of the step.

What students should finish with

  • The page loads with valid HTML boilerplate.
  • Bootstrap CSS and JS are linked correctly.
  • A titled container appears in the browser.

Questions to ask and the answers you want

Prompt for the class Expected answer / direction
What does <!DOCTYPE html> tell the browser? It tells the browser to render the page in standards mode as an HTML5 document.
Why does the Bootstrap CSS link go in the head? Because the page should know its styles before the body is rendered.
Why load the Bootstrap bundle near the end of the body? So the document exists before the script enhances components like modals.

HL variation

What changes when HL rebuilds this feature with JSON

The HL version uses the exact same HTML shell. No backend change matters yet because the page is still static.

HL note

The frontend stays the same here. Reuse the SQL HTML and JavaScript, then return to the HL backend pages when you swap out SQLite for JSON storage.

Watch for

Common mistakes to stop early

Teacher checks

  • Students forgetting to include the Bootstrap bundle script.
  • Putting content outside the body element.
  • Missing the link to /static/index.js, which will matter later.
