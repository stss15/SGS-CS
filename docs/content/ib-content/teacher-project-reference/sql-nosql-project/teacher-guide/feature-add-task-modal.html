Implementation step 3

Feature 3: Add-task modal

Students now add the interaction shell for creating tasks, but the inputs themselves are still the next lesson.

Teacher onlyExact target state

Teacher use on this page

Lesson focus, student target, and class answers

Use this as the teaching script for the live build. Start with the outcome, then use the build steps below to write the code in order.

What students should finish with

  • A visible Add Task button appears on the page.
  • Clicking the button opens a Bootstrap modal shell.
  • Students can identify the modal header, body, and footer.

Questions to ask and the answers you want

Prompt for the class Expected answer / direction
Why use a modal here? Because task creation is a temporary focused interaction without leaving the main list page.
Why keep the list page visible underneath? The modal supports the main task view rather than replacing it.
What belongs in the modal footer? The action buttons such as cancel and save.

Live build order

Step-by-step code to write with the class

Write these blocks in order. Each block is smaller than the final file so the teacher can explain what is happening before moving on.

Step 1

Write this in templates/index.html

Add the button that opens the modal

Start with the control the user clicks so the class can see how Bootstrap triggers work.

    <button
        class="btn btn-primary mb-3"
        data-bs-toggle="modal"
        data-bs-target="#taskModal">
        Add Task
    </button>

What this block does

  • data-bs-toggle="modal" tells Bootstrap what kind of component to open.
  • data-bs-target="#taskModal" points to the modal id that should open.
Step 2

Write this in templates/index.html

Write the modal shell

Only add the wrapper structure in this lesson. The form controls are the next deliberate step.

    <div class="modal fade" id="taskModal">
        <div class="modal-dialog">
            <div class="modal-content">
                <div class="modal-header">
                    <h5 class="modal-title">Create Task</h5>
                    <button class="btn-close" data-bs-dismiss="modal"></button>
                </div>
                <div class="modal-body">
                    <p class="text-muted mb-0">Form controls go here next.</p>
                </div>
                <div class="modal-footer">
                    <button class="btn btn-secondary" data-bs-dismiss="modal">Cancel</button>
                    <button class="btn btn-primary">Save Task</button>
                </div>
            </div>
        </div>
    </div>

What this block does

  • Teach the hierarchy: modal, modal-dialog, modal-content, then header, body, and footer.
  • The body is intentionally simple at this stage so students separate structure from inputs.

How the files link in this lesson

HL variation

What changes when HL rebuilds this feature with JSON

The HL version keeps the same modal shell. The storage model does not affect this part of the interface.

HL note

The frontend stays the same here. Reuse the SQL HTML and JavaScript, then return to the HL backend pages when you swap out SQLite for JSON storage.
