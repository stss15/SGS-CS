HL Stage 3

HL Stage 3: JSON data modelling comparison

Before HL students build the JSON version, compare two modelling options and make the teacher decision explicit.

Teacher onlyExact target state

Teacher objective

Use this lesson to justify the chosen HL model

Students should compare two JSON structures for the same idea and decide which one better matches the project and the SQL comparison.

Whole file after this step

Model A

TEXT 
users.json
[
  {"user_id": 1, "username": "Alice"},
  {"user_id": 2, "username": "Bob"}
]

tasks.json
[
  {"task_id": 1, "title": "Prepare slides", "user_id": 1}
]

Teaching notes for this file

  • Model A keeps user data separate and uses IDs to link tasks back to users.

Whole file after this step

Model B

TEXT 
tasks.json
[
  {
    "task_id": 1,
    "title": "Prepare slides",
    "user": {
      "user_id": 1,
      "username": "Alice"
    }
  }
]

Teaching notes for this file

  • Model B embeds user data inside every task, which makes reads simple but duplicates data.

Teacher answer key

What conclusion to steer them toward

The cleaner choice for this project is Model A.

Prompt for the class Expected answer / direction
Which model reduces duplication? Model A, because the user record is stored once and tasks reference it by id.
Which model aligns better with the SQL version? Model A, because it preserves the idea of relationships through identifiers.
Which model should the class implement for HL? Model A, with users.json and tasks.json kept separate.
