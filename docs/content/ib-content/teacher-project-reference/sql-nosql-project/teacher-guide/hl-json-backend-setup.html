HL Stage 4

HL Stage 4: JSON backend setup

Start the HL rebuild by swapping out SQLite for JSON files. The HTML and frontend flow from SL stay in place.

Teacher onlyExact target state

Teacher objective

What this HL lesson should establish

Students should understand that they are rebuilding the storage layer, not starting the whole app again.

Expected student output

  • A data folder with users.json and tasks.json.
  • An app.py file with JSON helper functions for reading and writing.
  • A clear explanation that the frontend can remain unchanged while the backend changes.

Questions and answers

Prompt for the class Expected answer / direction
Why keep the same HTML and JavaScript? Because the user-facing behaviour is the same; only the storage layer changes.
What replaces the SQL tables in HL? JSON files that hold arrays of objects.
Why do we need helper functions such as load_tasks() and save_tasks()? Because file reading and writing will happen repeatedly across routes.

app.py

PYTHON 
from flask import Flask, render_template
import json
import os

app = Flask(__name__)

TASK_FILE = "data/tasks.json"
USER_FILE = "data/users.json"


def load_tasks():
    if not os.path.exists(TASK_FILE):
        return []

    with open(TASK_FILE) as f:
        return json.load(f)


def save_tasks(tasks):
    with open(TASK_FILE, "w") as f:
        json.dump(tasks, f, indent=4)


def load_users():
    with open(USER_FILE) as f:
        return json.load(f)


@app.route("/")
def index():
    return render_template("index.html")


if __name__ == "__main__":
    app.run(debug=True)

Teaching notes for this file

  • At this point the backend knows where the JSON files live and how to load or save them.
  • Do not add the GET routes yet; those belong to the next lesson.

Teacher explanation

templates/index.html still serves the page, but the Python backend now reads users and tasks from JSON files instead of SQL queries. The browser does not care where the data comes from as long as the routes return the same shape.
