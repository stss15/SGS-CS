Stage 3

Stage 3: Database initialisation

Once the schema exists, create the database file and seed the starting users before the web build begins.

Teacher onlyExact target state

Teacher objective

Why this sits before the Flask build

Students should understand that the database must exist before the web app can read from it.

Expected student understanding

  • The schema file defines structure; it does not create the live database on its own.
  • The initial users are seed data, not hard-coded interface content.
  • Running python init_db.py is a one-time setup step for this stage.

Questions and answers

Prompt for the class Expected answer / direction
Why separate schema.sql from init_db.py? Because structure definition and setup logic are different jobs.
Why insert users here? Because the interface needs real users to populate the assignee dropdown.
When should this script run? After the schema is written and before the app tries to query the database.

init_db.py

PYTHON Open raw file 
import sqlite3


def init_database():
    conn = sqlite3.connect("tasks.db")

    with open("schema.sql") as f:
        conn.executescript(f.read())

    users = [
        ("Alice",),
        ("Bob",),
        ("Charlie",)
    ]

    conn.executemany(
        "INSERT INTO users (username) VALUES (?)",
        users
    )

    conn.commit()
    conn.close()

    print("Database created successfully.")


if __name__ == "__main__":
    init_database()

Teaching notes for this file

  • Open the schema file and execute it before inserting any data.
  • Seed the users table so the modal select has something to show later.
  • Run the script once, then check that tasks.db now exists.
