Stage 1

Stage 1: Problem specification

Read the client brief with the class, pull out the inputs and outputs, and agree the success criteria before any technical design starts.

Teacher onlyExact target state

Teacher objective

What this lesson is for

Students should leave this lesson knowing what the system is meant to solve and what the finished product must be able to do.

Teacher flow

  1. Read the problem brief aloud as if it has arrived from a client.
  2. Underline the operational problem, not the technical solution.
  3. Ask the class to list possible inputs and outputs.
  4. Convert those ideas into a set of measurable success criteria.

Expected student output

  • A notebook list of likely fields such as title, user, priority, due date, and status.
  • A list of visible outputs such as task rows, status text, and feedback after actions.
  • A first draft of 6 to 10 success criteria.

Client voice brief

Our team currently keeps track of jobs using spreadsheets and messages. This makes it hard to see who owns a task, when it is due, and whether it has been completed. We need one simple system that lets staff add tasks, assign responsibility, and see progress clearly.

Teacher answer key

Questions and answers for this page

These are the answers you are aiming to draw out when the class discusses the brief.

Prompt for the class Expected answer / direction
What is the real problem here? Task ownership and progress are unclear because work is split across spreadsheets and messages.
What are the likely inputs? Task title, assigned user, priority, and due date.
What are the likely outputs? A readable task list showing title, user, priority, due date, and status.
What constraints can we infer? The system must be simple, quick to use, and clear to non-technical staff.
What success criteria should the class settle on? Create, view, complete, delete, and later filter tasks, with persistent storage and clear presentation.

Success criteria

Teacher model answer

This is the clean set of outcomes the class should move toward before planning begins.

Suggested final criteria

  1. A user can create a task with a title, assignee, priority, and optional due date.
  2. The interface displays all current tasks clearly.
  3. The interface shows who owns each task.
  4. A user can mark a task as completed.
  5. A user can delete a task.
  6. The stored data persists after a refresh.
  7. The interface is simple enough to use without technical knowledge.
  8. The system can later be extended with automatically generated tags.
