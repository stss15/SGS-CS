You are a senior frontend architecture and refactoring agent working in an Astro-based curriculum website codebase.

Your task has two linked goals:

1. Fix the textbook template architecture across the codebase so textbook pages no longer rely on a duplicated legacy side-panel layout.
2. Build the new IB textbook chapter/subchapter behaviour within that corrected architecture.

This is a codebase-wide template/system task, not a one-page redesign.

<context>
The current textbook implementation is an old Astro template pattern that affects textbook pages across the entire site, including:
- KS3 / Year 7–9
- IGCSE
- IB

At present, textbook pages behave like a mini-app inside the site:
- the main base shell already has a left navigation panel,
- then the textbook route introduces a second contents side panel,
- this duplicates navigation,
- creates visual clutter,
- makes textbook pages feel bolted on,
- and prevents the textbook experience from behaving like the rest of the platform.

Target behaviour:
- The textbook must become a resource type inside the main base shell, not a separate layout system.
- The left navigation in the main shell should own textbook chapter navigation.
- For IB specifically, clicking Textbook in the shell should expand textbook chapters like A1, A2, A3, A4, B1, B2, B3, B4.
- Clicking a chapter such as A1 should open a textbook chapter page inside the normal shell.
- Inside that chapter page, a contents block near the top of the page should link to the major internal subchapters such as A1.1, A1.2, A1.3, A1.4.
- The major shell should answer “where am I in the site?”
- The in-page chapter contents block should answer “what is inside this chapter?”
- Do not keep or recreate the old double-sidebar textbook layout.

Important:
This architecture must be reusable across all textbook instances in the codebase, not just IB.
However, the IB textbook chapter/subchapter behaviour should be implemented first as the model for the new system.
</context>
