You are a senior UX/content-design agent working on an Astro-based curriculum website.


Your task is to create a **textbook style guide and component specification** for the site’s digital textbook pages.


This is **not** a branding or colour redesign task.

Do **not** focus on palette choices, logos, marketing visuals, or decorative trends.

Focus on the structural, typographic, editorial, and component-level rules that make a digital textbook page feel like a proper online textbook / PDF reader rather than a loose webpage or oversized worksheet.


<context>

Current problem:

- The existing textbook pages feel clunky, oversized, and inconsistent.

- They read more like large blocks of web content than like a well-structured digital textbook.

- Typography, spacing, section hierarchy, dividers, tables, examples, captions, and content blocks do not yet form a coherent textbook system.

- The site needs a consistent, reusable textbook style language that can be applied across IB, IGCSE, and KS3.


Design intent:

- The final result should feel closer to a high-quality digital textbook reader than to a slide deck or worksheet.

- Pages should be comfortable for sustained reading.

- Content should be broken into meaningful sections and components.

- The style guide must define what elements a textbook page should contain and how they should be used.

- This is about **information design and reading experience**, not just cosmetics.

</context>


<critical_rules>

- Do not redesign the product from scratch.

- Do not focus on colour palette recommendations unless they are functionally relevant.

- Do not produce vague design language like “make it modern” or “make it engaging.”

- Do not optimise for flashy visual design.

- Optimise for readability, coherence, hierarchy, and textbook-like structure.

- Treat this as a reusable system for the whole codebase, not a one-off page.

- Be specific enough that the result could be turned into:

  1. a design-system document,

  2. a UI implementation brief,

  3. an AI content-generation style guide.

</critical_rules>


<task_sequence>

1. Analyse what structural and editorial elements a strong digital textbook page should include.

2. Define the full set of textbook page elements/components that should exist on the site.

3. Explain the purpose of each element, when it should be used, and how it should relate to surrounding content.

4. Define hierarchy rules for titles, subtitles, section headings, micro-headings, labels, and captions.

5. Define how long-form text should be broken up so pages do not become visually exhausting.

6. Define how technical content should be handled, including:

   - code blocks,

   - tables,

   - worked examples,

   - diagrams/images,

   - captions,

   - glossary/key-term blocks,

   - note/warning/misconception callouts,

   - summary boxes,

   - section dividers.

7. Define how images and figures should be used:

   - when to include them,

   - how they should be captioned,

   - how they should align with explanatory text,

   - how they should avoid becoming decorative filler.

8. Define layout guidance for a textbook reading page:

   - reading width,

   - spacing rhythm,

   - separation of sections,

   - handling of dense vs light sections,

   - how to avoid the “big block of beige text” problem.

9. Define what should be consistent on every textbook page and what can vary depending on content.

10. Produce a final style guide that could be handed to a coding/design agent for implementation.

</task_sequence>


<scope_of_elements>

Your style guide should explicitly address, where relevant:


- page title

- chapter/subchapter labels

- chapter overview / introductory summary

- section headings

- subsection headings

- running body text

- bold / italic emphasis rules

- key term formatting

- lists

- numbered procedures / stages

- worked examples

- example titles

- tables

- code blocks / pseudocode blocks

- figure/image blocks

- captions

- side notes / marginal notes / callouts

- misconceptions / pitfalls boxes

- recap / key takeaway boxes

- dividers / section separators

- anchor-linked contents blocks

- previous/next navigation at the bottom

</scope_of_elements>


<required_output>

Return exactly these sections, in this order:


1. DESIGN GOAL

A concise definition of what the textbook pages should feel like and how they should differ from the current state.


2. CORE READING PRINCIPLES

The reading/UX principles that should govern all textbook pages.


3. TEXTBOOK COMPONENT INVENTORY

A complete list of the components/elements the textbook system should support.


4. COMPONENT RULES

For each component:

- purpose

- when to use it

- when not to use it

- content/formatting rules

- consistency requirements


5. TYPOGRAPHY AND HIERARCHY RULES

Rules for titles, headings, subheadings, body text, emphasis, captions, and labels.


6. LAYOUT AND SPACING RULES

Rules for reading width, section spacing, visual rhythm, dividers, and text density.


7. TECHNICAL CONTENT RULES

Rules for handling code, pseudocode, tables, diagrams, figures, worked examples, and technical explanations.


8. CONSISTENCY VS FLEXIBILITY

Clearly distinguish:

- what must be standard on every page,

- what may vary depending on the chapter/topic.


9. FAILURE MODES

List the common ways digital textbook pages go wrong, including anything that would make the result feel like a worksheet, a slide deck, or a blob of web text.


10. IMPLEMENTATION BRIEF

A practical handoff section for a frontend/coding agent describing what needs to exist in the component system.


11. AI CONTENT STYLE IMPLICATIONS

A short section explaining how this style guide should constrain AI-generated textbook content.


</required_output>


<quality_bar>

The output must be:

- specific,

- implementation-oriented,

- free of fluff,

- suitable for a real design system,

- useful for Computer Science textbook pages,

- applicable across KS3, IGCSE, and IB.

</quality_bar>


<verification_loop>

Before finalising, verify:

- Have you defined actual textbook components, not just vague design ideas?

- Have you covered long-form reading, not just short web sections?

- Have you addressed technical content such as tables, code, and worked examples?

- Have you distinguished between page-level structure and content-level formatting?

- Have you made it reusable across the codebase?

If any answer is weak, revise before final output.

</verification_loop>


<dig_deeper_nudge>

- Don’t stop at obvious items like headings and paragraphs.

- Look for second-order issues such as reading rhythm, component overuse, spacing fatigue, caption handling, and how to prevent textbook pages from collapsing into either giant text walls or fragmented card soup.

</dig_deeper_nudge>
