class – Blueprint/template defining shared attributes and methods for objects.
object – An instance of a class with its own state (data) and behaviour (methods).
instantiation – The process of creating an object from a class.
constructor – Special method that initialises a new object when it is created (e.g., `__init__` in Python).
attribute – A data field (variable) that belongs to an object/class.
method – A function that belongs to a class/object and defines behaviour.
encapsulation – Bundling data and methods together and restricting direct access to internal state.
access modifier – Language feature controlling visibility/access to class members (e.g., private/public/protected).
private – Accessible only within the class.
protected – Accessible within the class and its subclasses.
public – Accessible from any class.
accessor – “Getter”: method that returns the value of a private attribute.
mutator – “Setter”: method that updates the value of a private attribute (often with validation).
instance member – Belongs to a specific object; each object has its own copy.
static member – Class-level member shared by all instances; one copy exists for the class.
UML – Unified Modeling Language: standard way to describe system design (e.g., class diagrams).
inheritance – Is-a relationship where a subclass derives attributes/methods from a superclass.
superclass – Parent class that provides shared attributes/methods.
subclass – Child class that inherits from a superclass and can extend/override behaviour.
super – Keyword used to refer to/call a superclass method or constructor from a subclass.
overriding – A subclass provides a specific implementation of a method defined in its superclass.
polymorphism – Treating different classes through a shared interface/superclass so the same code works with multiple types.
abstract class – Class that cannot be instantiated and may define abstract methods to be implemented by subclasses.
interface – Contract specifying method signatures that implementing classes must provide.
composition – Strong has-a relationship where the part’s lifetime depends on the whole.
aggregation – Weak has-a relationship where the part can exist independently of the whole.
design pattern – Reusable general solution/structure to a commonly occurring design problem.
singleton – Pattern that restricts a class to a single instance and provides global access to it.
factory pattern – Pattern that creates objects through a common interface without specifying the exact class in client code.
observer pattern – Subscription mechanism where observers are notified automatically when a subject’s state changes.
