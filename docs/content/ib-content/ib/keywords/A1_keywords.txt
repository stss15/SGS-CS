ALU – Arithmetic Logic Unit: performs arithmetic operations and logical comparisons.
CU – Control Unit: decodes instructions and co-ordinates CPU operations using control signals.
CPU – Central Processing Unit: executes program instructions and controls the operation of the computer.
register – Small, high-speed storage location inside the CPU used to hold data, addresses, or instructions temporarily.
instruction register (IR) – Stores the instruction currently being decoded/executed.
program counter (PC) – Stores the address of the next instruction to fetch from memory.
memory address register (MAR) – Stores the address in memory that will be read from or written to.
memory data register (MDR) – Stores data that has just been read from memory or is about to be written to memory.
accumulator (AC) – Stores intermediate arithmetic/logic results produced by the ALU.
opcode – Operation code: the part of an instruction that specifies what operation to perform.
bus – Shared communication pathway used to transfer data, addresses, and control signals between components.
data bus – Carries data between CPU, memory, and I/O devices; typically bidirectional.
address bus – Carries memory addresses from CPU to memory; width determines maximum addressable memory.
control bus – Carries control signals (e.g., read/write, interrupts, clock) used to co-ordinate operations.
volatile – Loses its contents when power is removed.
non-volatile – Retains its contents when power is removed.
RAM – Random Access Memory: volatile primary memory holding programs and data currently in use.
ROM – Read-Only Memory: non-volatile memory storing firmware/boot instructions (e.g., BIOS/UEFI).
cache – Small, fast memory that stores frequently used data/instructions to reduce RAM access time.
L1 cache – Smallest, fastest cache; typically per-core and closest to CPU execution units.
L2 cache – Larger, slightly slower cache; often per-core or close to the core.
L3 cache – Largest, slowest cache; often shared between cores.
cache hit – When requested data is found in cache (fast access).
cache miss – When requested data is not in cache and must be fetched from slower memory/storage.
prefetching – Loading predicted data/instructions into cache before they are needed to reduce cache misses.
memory hierarchy – Organisation of storage by speed/cost/capacity (registers → cache → RAM → secondary storage).
core – An independent processing unit within a CPU capable of executing instructions.
single-core processor – CPU with one core; handles one instruction stream at a time (multitasking via scheduling).
multi-core processor – CPU containing multiple cores to run multiple instruction streams in parallel.
co-processor – Specialised processor designed to offload specific tasks from the CPU (e.g., GPU, DSP).
graphics processing unit (GPU) – Co-processor optimised for highly parallel computations (e.g., graphics rendering, matrix operations).
parallel processing – Performing multiple computations simultaneously by dividing work across multiple processing units/cores.
fetch–decode–execute cycle – Repeated CPU process: fetch instruction, decode it, then execute it.
pipelining – Overlapping instruction stages so multiple instructions are in progress simultaneously, increasing throughput.
throughput – Amount of work completed per unit time (e.g., instructions per cycle).
latency – Time taken for one instruction/task to complete from start to finish.
bit – Binary digit: a single 0 or 1.
byte – 8 bits.
binary – Base-2 number system using digits 0 and 1.
denary – Base-10 number system.
hexadecimal – Base-16 number system using digits 0–9 and A–F (4 bits per digit).
encoding – A rule/system that maps symbols or values to binary patterns.
noise – Unwanted electrical disturbance that can corrupt digital signals (not sound noise).
ASCII – Character encoding that maps characters to numeric codes (historically 7-bit, with extended variants).
Unicode – Universal character set mapping characters to code points for many languages/symbols.
pixel – Smallest unit of a digital image (picture element).
resolution – Width × height of an image in pixels.
colour depth – Number of bits used to represent the colour of one pixel.
compression – Reducing file size by representing the same information using fewer bits.
lossless compression – Compression that preserves all original information when decompressed.
lossy compression – Compression that permanently discards some information to reduce size.
sampling rate – Number of samples taken per second when digitising sound (Hz).
bit depth – Number of bits used to store each sample value (amplitude) in digital audio.
logic gate – A basic digital circuit component that performs a Boolean operation on binary inputs.
truth table – Table of all input combinations and corresponding output(s) of a Boolean function/circuit.
logic diagram – Diagram showing logic gates connected to implement a Boolean function.
Gray code – Binary ordering where adjacent values differ by exactly one bit (e.g., 00, 01, 11, 10).
Karnaugh map – Visual method for simplifying Boolean expressions by grouping 1s in a Gray-code-ordered grid.
operating system (OS) – System software that manages hardware resources and provides services for applications.
virtual memory – Memory-management technique that uses disk storage to extend usable memory beyond physical RAM.
device driver – Software that allows the operating system to communicate with and control a specific hardware device.
buffering – Temporarily storing data during transfer to handle speed differences between devices/processes.
spooling – Queuing data for a device (e.g., printer) so multiple jobs can be handled in order.
defragmentation – Reorganising data on an HDD so file blocks are stored contiguously, improving access speed.
interrupt – Signal that causes the CPU to pause its current task and execute an interrupt handler for an event.
polling – Repeatedly checking a device/status at intervals to see if an event has occurred.
time slice (quantum) – Fixed amount of CPU time a process may use before being pre-empted (e.g., in round robin).
starvation – When a process waits indefinitely because higher-priority processes keep being scheduled.
deadlock – State where processes are stuck waiting for each other’s resources so none can proceed.
sensor – Input device that measures a physical quantity and converts it into a signal.
actuator – Output device that converts a control signal into physical action (movement, heat, flow).
transducer – Device that converts energy from one form to another; sensors and actuators are types of transducers.
setpoint – The desired target value a control system aims to maintain.
error signal – The difference between target state (setpoint) and actual state in a control system.
source code – Human-readable program written in a high-level programming language.
machine code – Binary instructions executed directly by a CPU (architecture-specific).
interpreter – Program that translates and executes source code line-by-line at runtime.
compiler – Program that translates source code into machine code (or an intermediate form) before execution.
object code – Output of compilation, typically machine code that may need linking to form an executable.
executable – Machine-code program file that can be run directly by the operating system/CPU.
bytecode – Intermediate code designed to be executed by a virtual machine (VM), not directly by a CPU.
virtual machine (VM) – Software that runs bytecode by emulating/exposing a platform-independent runtime environment.
just-in-time (JIT) compilation – Runtime compilation that converts frequently executed bytecode (“hot spots”) into machine code for speed.
