A2 Networks: Educator's Implementation Guide

This guide provides the technical breakdown of computer networks for Cambridge IGCSE and IB curricula, including Higher Level (HL) architectural and security concepts.

2. Modern Digital Infrastructure

  • Distributed Systems: Multiple nodes working toward a common goal. Focus on fault tolerance (no single point of failure) vs. consistency challenges.
  • Edge Computing: Processing data at the "edge" of the network (near the source) to reduce latency and bandwidth load. Example: Netflix local caching servers.
  • Mobile Networks: 5G mechanics—increased speeds (up to 10 Gbps) and low latency supporting IoT growth.

A2.2: Network Architecture

1. The Hardware Stack (Functionality)

  • Gateways: Translators between disparate protocols. Operates primarily at the Application Layer.
  • Routers: Use IP addresses to determine the optimal path between networks.
  • Switches: Use MAC addresses to direct traffic within a single network segment (Star topology).
  • Modems: Modulator-Demodulator. Converts between Analogue (ISP line) and Digital (Router) signals.

2. Networking Models

  • Client-Server: Centralised control. Server provides, client requests. Drawback: Single point of failure.
  • Peer-to-Peer (P2P): Decentralised. Every node is both client and server. Example: BitTorrent, Blockchain.

A2.3: Data Transmission (Technical Depth)

1. The TCP/IP Model (HL)

Students must explain the Encapsulation process from top to bottom:

  • Application Layer: HTTP, HTTPS, SMTP, FTP. (Data is formatted).
  • Transport Layer: TCP (Connection-oriented, 3-way handshake) or UDP (Connectionless, low overhead). Data becomes Segments.
  • Internet Layer: IP (Routing). Data becomes Packets.
  • Network Interface Layer: MAC addressing and physical transmission. Data becomes Frames.

2. Packet Switching Mechanics

  • Segmentation: Breaking large data into MTU-sized packets (typically 1500 bytes).
  • Header Metadata: IP addresses, Sequence Numbers (for reassembly), and Checksums (for error detection).
  • Independent Routing: Packets may take different paths; arrival order is not guaranteed.

3. Subnetting & CIDR Logic

  • Bitwise AND: Students must be able to calculate the Network Address by performing a bitwise AND between an IP and its Subnet Mask.
  • NAT (Network Address Translation): Mapping Private IP ranges (e.g., 192.168.x.x) to a single Public IP to conserve IPv4 space and provide obscurity.

A2.4: Network Security

1. Common Vulnerabilities (HL)

  • DDoS: Overwhelming a target with traffic from multiple compromised sources (Botnets).
  • SQL Injection: Injecting malicious SQL commands into input fields to manipulate backend databases.
  • Man-in-the-Middle (MitM): Intercepting/altering communication between two parties. Countered by Encryption.

2. Encryption Mechanics (HL)

  • Symmetric: Same key for encryption/decryption (Fast, requires secure key exchange).
  • Asymmetric (Public Key): Different keys. Public key encrypts, Private key decrypts. (Solves key distribution).
  • Digital Certificates: Issued by a Certificate Authority (CA) to prove ownership of a public key. (Essential for HTTPS/SSL/TLS).
  • Diffie-Hellman: A mathematical method for two parties to agree on a shared secret key over an insecure channel without actually sending the key itself.

Pedagogical Tips & Boundaries

  • The TCP Handshake: Teach the SYN -> SYN-ACK -> ACK sequence. It is a frequent exam diagram question.
  • Transmission Media: Compare Fibre-optic (high speed, immune to EMI) vs. Twisted-pair (cheap, flexible) vs. Wireless (susceptible to interference).
  • Static vs. Dynamic Routing: Static is predictable and low-overhead (small networks); Dynamic (e.g., RIP, OSPF) is scalable and fault-tolerant (large networks).
  • Firewalls: Distinguish between Packet Filtering (Headers only) and Stateful Inspection (Monitoring active connection states).
