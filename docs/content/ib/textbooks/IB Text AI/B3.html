B3 Object-Oriented Programming (OOP): Educator's Implementation Guide

This guide addresses the transition from procedural to object-oriented programming, covering Fundamentals, Class Design, and Multiple Classes (HL) for IGCSE and IB curricula.

B3.1: Fundamentals of OOP

1. Key Terminology

Term Definition
Class A blueprint or template for creating objects; defines shared properties and behaviours.
Object An instance of a class containing its own data (state) and methods (behaviour).
Instantiation The process of creating a specific object instance from a class template.
Constructor A special method (__init__ in Python) that initialises a new object.

2. Encapsulation & Access Modifiers

  • Encapsulation: Bundling data and methods into a single unit and restricting direct access to internal state.
  • Access Modifiers (Java):
    • Private: Accessible only within the class.
    • Protected: Accessible within the class and its subclasses.
    • Public: Accessible from any class.
  • Accessors & Mutators: Commonly known as Getters and Setters. Used to maintain control over private variables.

3. Static vs. Non-Static

  • Static (Class-level): Variables or methods that belong to the class itself. Only one copy exists, shared by all instances.
  • Non-Static (Instance-level): Variables or methods that belong to a specific object. Each instance has its own unique copy.

B3.2: Multiple Classes & Relationships (HL)

1. Inheritance & Polymorphism

  • Inheritance ("Is-a" relationship): A subclass derives properties and behaviours from a superclass.
    • Super() keyword: Used to call the constructor of the parent class.
  • Polymorphism: The ability of different classes to be treated as instances of the same superclass through a shared interface.
  • Overriding: A subclass providing a specific implementation of a method already defined in its superclass.

2. Abstraction & Interfaces

  • Abstract Class: A template that cannot be instantiated itself. It enforces a contract by requiring subclasses to implement specific methods.
  • Interface: A set of method signatures that a class must implement (e.g., a "contract").

3. Composition vs. Aggregation ("Has-a")

  • Composition: A strong relationship where the life of the "part" depends on the "whole" (e.g., Human and Heart).
  • Aggregation: A weak relationship where the "part" can exist independently of the "whole" (e.g., Library and Book).

B3.2.5: Design Patterns

  • Singleton Pattern: Restricts a class to a single instance (e.g., a database connection manager).
  • Factory Pattern: Provides an interface for creating objects without specifying the exact class (promotes flexibility).
  • Observer Pattern: A "subscription" mechanism to notify multiple objects about events happening to the object they are observing.

Boundaries & Pedagogical Tips

  • Naming Conventions: Classes should be singular nouns (BankAccount), methods should be verbs (deposit()).
  • UML Design: Encourage students to draw 3-row UML diagrams (Name, Attributes, Methods) before coding.
  • The Paradigm Shift: Students often struggle to "think in objects". Use the "Blueprint vs. House" analogy to differentiate Classes from Objects.
