database – An organized collection of related data stored so it can be accessed, managed and updated efficiently.
DBMS (database management system) – Software that creates, maintains, secures and provides access to a database.
relational database – Database model that stores data in related tables (relations) connected by keys.
table (relation) – A structured set of data stored in rows and columns.
record (row/tuple) – One complete set of fields describing a single entity instance in a table.
field (column/attribute) – A single category of data stored for each record in a table.
entity – A real-world object or concept represented in a database (e.g., Student, Order).
relationship – Logical association between entities/tables (often implemented using keys).
primary key – Field (or set of fields) that uniquely identifies a record in a table.
foreign key – Field (or set of fields) in one table that references a primary key in another table.
composite key – Primary key made from two or more fields combined to create uniqueness.
referential integrity – Constraint ensuring every foreign key value matches an existing primary key (or is null where allowed).
cardinality – The “how many?” nature of a relationship (e.g., one-to-many).
one-to-one (1:1) – Relationship where each record in one table matches at most one record in another.
one-to-many (1:m) – Relationship where one record relates to many records in another table.
many-to-many (m:m) – Relationship where many records relate to many records (implemented with a junction table).
junction table – Table used to represent a many-to-many relationship by storing pairs of foreign keys.
redundancy – Unnecessary duplication of data that increases storage and can cause inconsistencies.
update anomaly – Inconsistency caused when duplicated data is updated in some places but not others.
insert anomaly – Problem caused when required data cannot be inserted without adding unrelated data.
delete anomaly – Loss of important data when deleting a record that also stores other facts.
database schema – Blueprint describing how a database is structured (tables, fields, relationships, constraints).
conceptual schema – High-level model of data requirements (often an ERD), independent of implementation.
logical schema – Detailed design of tables, fields, keys, and relationships for a chosen data model.
physical schema – Implementation details in a DBMS (storage, indexes, partitions, access paths).
ERD (entity–relationship diagram) – Diagram showing entities, attributes, and relationships (with cardinality).
attribute – Property/field of an entity (e.g., Student has Name, DOB).
constraint – Rule enforced by a DBMS to maintain valid data (e.g., NOT NULL, UNIQUE).
data type – Classification defining what values a field can store (e.g., INTEGER, VARCHAR, DATE).
normalization – Process of structuring tables to reduce redundancy and improve integrity.
1NF (first normal form) – Table with atomic values (no repeating groups) and a primary key.
2NF (second normal form) – 1NF plus no partial dependency on part of a composite key.
3NF (third normal form) – 2NF plus no transitive dependencies (non-key depends only on the key).
denormalization – Deliberate introduction of redundancy (e.g., duplicated fields) to improve performance or reporting.
SQL (structured query language) – Language used to define, query and modify relational data.
DDL (data definition language) – SQL commands that create/modify database structures (CREATE, ALTER, DROP).
DML (data manipulation language) – SQL commands that query/modify data (SELECT, INSERT, UPDATE, DELETE).
DCL (data control language) – SQL commands that control permissions (GRANT, REVOKE).
TCL (transaction control language) – SQL commands that manage transactions (COMMIT, ROLLBACK).
query – A request to retrieve or modify data in a database.
JOIN – SQL operation combining rows from two tables based on a related field.
aggregate function – SQL function that returns a single value from many rows (COUNT, SUM, AVG, MIN, MAX).
GROUP BY – SQL clause that groups rows so aggregates can be calculated per group.
view – Virtual table defined by a query; presents data without storing a separate copy (unless materialized).
transaction – A sequence of database operations treated as one unit of work.
ACID – Transaction properties: Atomicity, Consistency, Isolation, Durability.
COMMIT – TCL command that permanently saves the changes made in a transaction.
ROLLBACK – TCL command that undoes changes made in a transaction since the last commit.
NoSQL – Family of non-relational databases designed for scalability and flexible data models.
document database – NoSQL database storing data as documents (e.g., JSON-like objects).
key–value store – NoSQL database storing data as key → value pairs for fast lookup.
wide-column store – NoSQL database storing data in flexible column families optimized for large-scale storage.
graph database – NoSQL database storing data as nodes and edges, optimized for relationship queries.
data warehouse – Centralized store optimized for analysis/reporting, often integrating data from multiple sources.
ETL (extract, transform, load) – Process of moving and cleaning data from sources into a data warehouse.
OLAP (online analytical processing) – Techniques for analyzing multidimensional data (trend analysis, roll-up, drill-down).
data mining – Process of discovering patterns/relationships in large data sets.
distributed database – Database with data stored across multiple machines/locations, presented as one system.
replication – Keeping copies of data on multiple nodes for availability and performance.
sharding (fragmentation) – Splitting data across nodes so each stores a subset (improves scale).
eventual consistency – Model where replicas may temporarily differ but converge over time.
