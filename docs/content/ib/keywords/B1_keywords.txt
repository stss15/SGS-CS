stakeholder – Any individual or group with an interest in the success or failure of a system.
problem specification – Clear definition of objectives, requirements, constraints/limitations, inputs/outputs, and success criteria.
evaluation criteria – Specific, measurable metrics used to judge the success of a final product.
requirement – A condition or capability the system must satisfy to meet stakeholder needs.
constraint – A restriction that limits solution options (e.g., budget, legal rules, hardware).
limitation – A practical boundary on what the system can achieve (e.g., accuracy limits, network availability).
input device – Hardware used to enter data into a system (manual, automatic, or direct data entry).
output device – Hardware used to present results (temporary, permanent, or physical/mechanical).
OCR – Optical Character Recognition: converts images of text into machine-readable text.
OMR – Optical Mark Recognition: detects filled-in marks on paper forms (e.g., exam sheets).
MICR – Magnetic Ink Character Recognition: reads characters printed with magnetic ink (e.g., cheques).
GDPR – European data protection law regulating how personal data is collected, stored, and processed.
abstraction – Focusing on essential information while ignoring irrelevant detail to create a simplified model.
decomposition – Breaking a problem into smaller manageable sub-problems before coding.
pattern recognition – Identifying similarities to reuse solutions and build general rules.
algorithmic thinking – Designing a finite, ordered set of unambiguous steps to solve a problem.
algorithm – Finite, ordered set of unambiguous steps that produces an outcome for valid inputs.
flowchart – Diagram that represents an algorithm using standard symbols and flow lines.
trace table – Table used to track variable values and outputs step-by-step through an algorithm.
MOD – Returns the remainder after integer division.
DIV – Integer division returning the quotient without remainder.
pseudocode – Language-agnostic description of an algorithm using structured, readable statements.
IPO – Input–Process–Output: framework describing what data enters, how it is transformed, and what results are produced.
stepwise refinement – Gradually increasing detail by breaking a solution into smaller steps until it is implementable.
verification – Checking that a solution matches its design/specification (did we build it right?).
validation – Checking that a solution meets user needs (did we build the right thing?).
